# M15 macOS 免费分发

本次覆盖 F-REL-001、F-REL-002，以及 F-REL-003 的整包复制验收。不需要付费 Apple 开发者证书，也不在安装或更新时要求用户重新签名。

## 1. 打包合同

- 本地 `scripts/bundle-macos.sh` 和 CI 的 Intel、Apple Silicon 发布共用临时签名脚本。二进制、图标和 Info.plist 全部就绪后才签完整 `.app`，签完不再修改包内容。
- 无证书时使用 `codesign --sign - --timestamp=none`。当前应用仅有一个主可执行文件；如引入嵌套代码，先分别由内到外签好，再签外层应用，不用 `--deep` 代替签名顺序。
- 所有发布路径在封装 DMG 前执行 `codesign --verify --deep --strict --all-architectures`；签名或验签失败时停止，不上传产物。临时签名不使用正式分发的 Hardened Runtime 和 Entitlements。
- 有证书时保留现有 Developer ID 签名与时间戳，不能被临时签名覆盖。公证必须同时配置证书和 Apple 凭据；只有公证凭据时不能把临时签名包送去公证。

## 2. 安装与更新边界

- 推荐无管理员权限的用户安装到 `~/Applications`；现有 `/Applications` 安装仍可使用，是否需要管理员权限取决于目录和应用的实际写权限。
- 更新器继续挂载 DMG、复制完整 `.app` 并替换旧包，失败时恢复旧包；不在客户端重新签名，也不自动移除下载隔离标记或修改系统 Gatekeeper 设置。
- 临时签名只校验内容完整性，不证明开发者身份，也不等于 Apple 公证。首次启动或某次升级仍可能要求“系统设置 → 隐私与安全 → 仍要打开”。签名已损坏的包不能靠这一步修复，应重新下载正确的产物。
- 临时签名不能解决钥匙串授权随构建身份变化的问题；12-secrets.md 中的正式签名遗留仍然保留。

## 3. 验收

- [x] 在真实 macOS 工具上给带空格路径的最小应用签名，严格验签并运行成功，无 `sudo` 或证书。
- [x] 签名后修改资源，严格验签必须失败；不能发布签名已失效的产物。
- [x] 制作、挂载 DMG，再按更新器的 `ditto` 与整包替换流程复制到用户可写目录，签名仍有效且程序可运行。
- [x] 本地完整 Navidog 应用经过签名、DMG 复制后严格验签与首帧冒烟成功。
- [x] macOS 两个架构的常规 CI 接入签名回归检查；发布工作流无证书时走临时签名，有证书时保留正式签名（本机检查了配置，远端运行待验证）。

本机只证明当前架构；Intel CI、公证和实际浏览器下载后的系统放行另行记录，不由本机签名完整性检查代替。
