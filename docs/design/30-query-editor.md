# M3 规格：查询编辑器

覆盖功能：
- **查询编辑器**：F-QRY-001 ~ F-QRY-005、F-QRY-010、F-QRY-011；
- **信息窗格**：F-INFO-004 ~ F-INFO-006；
- **应用与偏好设置**：F-APP-016、F-PREF-004、F-PREF-006、F-PREF-008。

运行、结果、解释、历史日志和命令列界面见 [31-query-results.md](31-query-results.md)。查询创建工具（F-QRY-013）移到 M7，与 ER 图共用一套画布。

行为来源：`query.html`、`query_editor.html`、`query_code_snippet.html`、`information_pane.html`、`preferences_editor.html`、`preferences_code_completion.html`、`preferences_auto_recovery.html`、`hot_keys.html`。

尺寸来源：`QueryDesignSQLEditorModule`、`SQLEditorModule_Snippet`、`SnippetViewController`、`SQLEditorModule_ObjectList`、`SQLBeautifyOptionPanel`、`AutoRecoverWindowController`、`PreferencesEditorModule`、`PreferencesCodeCompletionModule`、`PreferencesAutoRecoveryModule`。查询设计器本身的 nib（`QueryDesignViewController`）是空的，工具栏和菜单在代码里搭建，按钮和菜单项按帮助页和各 nib 的 `.strings` 排列和命名。

本里程碑新建 crate `navidog-query`，放查询编辑器、结果选项卡、解释、命令列界面和历史日志查看器。它依赖 `navidog-grid` 复用结果网格和提交流程，这是总览 4.1 节允许的唯一一条 feature crate 之间的依赖。

## 1. 技术验证：SQL 编辑器（M3 开工后先做，结论写回本节）

gpui-kit 0.7.3 的 `EditorState::new(window, cx).language("sql")` 已经提供：
- 行号、软换行、制表符宽度和硬制表符、缩进线，都可以在运行时切换；
- 代码折叠（折叠区间来自 tree-sitter）；
- 增加和减少缩进（`Indent`、`Outdent`）；
- 查找替换面板：字面量匹配、大小写开关、替换、全部替换、即时高亮；
- 补全接口 `CompletionProvider`：自带浮层，每项是标签加说明，默认选中第一项，回车确认；
- 诊断（`Diagnostic`），在文字下方画彩色波浪线；只读模式；可以整体替换的右键菜单；
- 文本接口：`value`、`selected_range`、`cursor`、`insert`、`replace`、`set_selected_range`。

Navicat 的编辑器还需要以下能力，在外层补：

| 需求 | 现状 | 在外层实现的方式 |
| --- | --- | --- |
| 括号高亮 | 没有 | 光标挨着括号时，自己找到配对的括号（跳过字符串和注释），用区间装饰画出来（见判定规则） |
| 查找的正则表达式、整个字 | 内置查找只匹配字面量 | 关掉内置查找（`searchable(false)`），自建查找栏，用 `regex` crate（已在依赖树中）匹配；全部匹配用区间装饰高亮，当前匹配用选区表示 |
| 代码段占位符 | 补全原样插入文本，没有跳转点 | 插入后记下各占位符的区间，Tab 和 ⇧Tab 在区间之间移动并选中；占位符用区间装饰涂浅绿色 |
| 切换注释、转换大小写、简化 SQL | 没有 | 用 `selected_range` 和 `replace` 改写选中的行或文字，一条命令对应一次撤销 |
| 剪贴板堆栈 | `Copy`、`Cut` 不发事件 | 在编辑器外层捕获 `Copy`、`Cut` 动作，先记下选中的文字，再让动作照常执行 |
| 拖放插入 | 编辑器没有 `on_drop`，坐标到文本位置的换算不公开 | 外层 `on_drop` 接收拖入的文字，插到光标处而不是落点（偏差） |
| Tab 确认补全、Esc 打开补全 | Tab 是缩进；Esc 只会关闭补全菜单，打开菜单没有快捷键 | 补全菜单打开时，外层把 Tab 换成确认；菜单关着时，Esc 派发 `ShowCompletions` |
| 缩放 | 没有运行时缩放 | 外层按缩放倍数给 `Editor` 设字号 |
| 超过阈值关闭高亮和补全 | 没有开关 | 文本超过阈值时把语言换成纯文本，并卸下补全接口 |
| 方言关键字 | 只有通用的 `sql` 语法 | 高亮共用通用语法；补全的关键字和内置函数按方言给出，列表放在 `navidog-db` 的方言里 |
| 快捷键冲突 | 编辑器把 ⌘. 绑给代码操作，⌘⇧F 绑给替换 | 在查询编辑器的 key context `QueryEditor` 里改绑：⌘. 停止，⌥⌘F 查找和替换 |

**判定规则**：括号高亮、查找匹配和占位符都要“给一段文字换背景色”。先看语义标记（`DocumentRangeSemanticTokensProvider`）的样式能否带背景色；不能就退回用提示级诊断的下划线标出；两者都不行时，三项都只用选区表示，记为偏差。无论哪种都不 fork gpui-kit。另外，打开 5 万行（约 2 MB）的 SQL 后输入和滚动，单帧不超过 8.3ms；超出时调低“禁用语法高亮显示和代码补全”的默认阈值（第 9 节）。

**结论：继续用 `EditorState`，三项都用区间装饰。** 语义标记的样式按名字从主题取，加不了背景色，但 gpui-kit 另有两种区间装饰，区间都会随编辑自动移动：
- `create_range_decorations_collection`：`RangeDecoration` 画成填充（`Fill`）或一像素边框（`Frame`），可以指定颜色。括号高亮用边框，查找的全部匹配用填充，占位符用浅绿色填充；
- `create_decorations_collection`：`TextDecoration` 用 `HighlightStyle` 改文字样式，也能带背景色，暂时用不到。

其余几项的做法也已确认：
- **Tab 确认补全**：`completion_menu_state().open` 能读到菜单是否打开；打开时把 Tab 换成 `route_overlay_action(Enter)` 交给菜单确认。菜单关着时 Esc 调 `show_completions`。
- **关掉“自动选择第一个建议项目”**：补全菜单打开时总是选中第一项，改不了。记下打开菜单后有没有按过方向键；没按过时回车和 Tab 先关掉菜单，再照常换行、缩进。第一项仍然画成选中的样子（偏差）。
- **缩放和编辑器字体**：`Editor` 默认用主题的等宽字体和字号，`text_size`、`font_family` 可以按编辑器覆盖，行高跟着字号变。
- **查找**：编辑器的查找引擎可以脱离自带面板使用（`set_search_query` 等），但只认字面量和大小写；为了一条路径支持正则表达式和整个字，匹配仍由我们自己算，高亮用填充装饰。

验证程序是 `cargo run --release -p navidog-query --example editor_spike`（1440 × 900 的 headless Metal 窗口，5 万行、2.8 MB 的 SQL，各测 300 帧）。后台解析完成、全文上色以后：

| 场景 | 平均 | p95 | 最大 | 超过 8.3ms 的帧 |
| --- | --- | --- | --- | --- |
| 逐行滚动（每帧 3 行） | 2.9ms | 4.0ms | 8.8ms | 1 / 300 |
| 跳跃滚动（每帧 997 行） | 2.9ms | 3.6ms | 11.3ms | 2 / 300 |
| 带 3000 个填充装饰逐行滚动 | 2.7ms | 3.1ms | 4.8ms | 0 / 300 |
| 文档中部连续输入 | 2.6ms | 3.2ms | 4.7ms | 0 / 300 |

- 首次解析并上色约 0.4 秒。超过 256 KB 或同步解析超过 2ms 的文本在后台解析（先等 150ms），这段时间里文字没有颜色；输入时旧的颜色跟着编辑移动，新解析完成后刷新。
- 偶发的超时帧来自第一次排版没见过的文本，与结果网格（21 第 1 节）相同。高亮阈值的默认值 10 MB 保持不变。
- 未上色时测得的帧时间约 1.4ms，那是一个测量假象：headless 测试用的调度器只在推进时钟时才触发定时器，后台解析前的 150ms 一直没走完。验证程序和 UI 测试都要用 `advance_clock` 推进时钟（AGENTS.md 已记录）。

## 2. 查询选项卡

```
┌────────────────────────────────────────────────────────────────────────────┐
│ 工具栏第一行（高 30）：保存 | 美化 SQL  代码段  查询创建工具                    │
│ 工具栏第二行（高 30）：[连接 ▾][数据库 ▾][模式 ▾]  运行 ▾  遇到错误时继续  停止  解释 │
├────────────────────────────────────────────────────────────────────────────┤
│ 编辑器（行号、折叠）                                                         │
├───────────────────────────── 可拖动的分隔条 ───────────────────────────────┤
│ 结果区：消息 | 摘要 | 结果 1 | 结果 2 …（见 31-query-results.md 第 4 节）      │
└────────────────────────────────────────────────────────────────────────────┘
```

- **标题**：`名称 @数据库 (连接名)`，例如 `无标题 @sakila (本地)`。没保存过的名称叫“无标题”，再开一个叫“无标题 2”，依次递增。数据库或连接还没选时，缺的那一段不写，只剩名称。PostgreSQL 的模式不进标题，只在工具栏的模式下拉里。标题前是查询图标，悬停显示全文。面板照 AGENTS.md 接入 `navidog_ui::tabs`，可以关闭、弹出为新窗口、加到收藏夹和启动画面（无标题的查询不能加）。激活已保存的查询时，工作区选择设为这个查询；无标题的查询不改选择。
- **布局**：编辑器和结果区默认上下各占一半，分隔条位置对所有查询编辑器统一记住。结果区的三种位置见 31 第 4.1 节。
- **工具栏**：两行，每行高 `query.toolbar.height`。“连接”“数据库”“模式”决定在哪里运行（31 第 2 节），也决定代码补全用哪份信息、保存到哪里；“模式”只在 PostgreSQL 出现。这三个是带边框的选择外观（浅底、左侧图标、右侧箭头），点开仍是原生菜单。“查询创建工具”在 M7 之前显示为禁用。“代码段”打开信息窗格的代码段页。“遇到错误时继续”与运行菜单里的同一项共用设置。结果位置是“新页面”且已经有结果、当前又停在编辑器时，第二行有“显示结果”。右侧有专注模式开关，与表查看器相同（F-APP-008）。主工具栏的“新建查询”和“查询”按钮在 M3 启用。
- **未保存的修改**：选项卡标题末尾显示 ●，⌘W、右键菜单的关闭、点 ● 都先询问“是否保存对查询的更改？”：取消（Esc）、不保存、保存（回车）。机制与表查看器相同（`navidog_ui::tabs` 的关闭守卫）。
- **关闭连接时不关闭**：查询编辑器是文档，关闭连接时只断开它自己的会话，下次运行时重新打开连接。这与表查看器（F-CONN-012）不同，避免丢掉没保存的 SQL。

## 3. 编辑（F-QRY-001、F-QRY-003 ~ F-QRY-005）

- **高亮与外观**：tree-sitter SQL 语法高亮，配色取 `themes/navicat.json` 的 `syntax.*`，本里程碑与 Navicat 并排实测后替换现在沿用的 gpui-component 默认值（progress 第 4 节的遗留）。行号、代码折叠、括号高亮、语法高亮分别受偏好设置控制（第 9 节）。不自动补右括号和引号（`auto_close` 关闭）。
- **字体**：等宽字体 `font.mono_family`，字号 `editor.font_size`；偏好设置取消“使用默认字体”后用设置的字号。
- **自动换行**：“查看 > 自动换行”切换当前编辑器；新编辑器取偏好设置“使用自动换行”的值。
- **缩放**：“查看 > 放大”（⌘+）、“缩小”（⌘-）、“实际大小”（⌘0），每次 1pt，范围 8 ~ 72。只影响当前编辑器，不写进偏好设置。
- **格式菜单**：只在查询编辑器激活时出现在菜单栏里（10 第 9 节）。
  - 缩排 ▸ 增加缩排（⌘]）、减少缩排（⌘[）；
  - 注释 ▸ 注释行、取消注释行；切换注释（⌘/）。注释符是行首的 `-- `；选中的行里只要有一行没有注释，“切换注释”就给所有行加上；
  - 转换大小写 ▸ 大写、小写：按选中的文字整体转换；
  - 美化 SQL、美化 SQL 选项…、简化 SQL，见下面三条。

  缩排和注释作用于选中的行，没有选中时作用于光标所在行；其余命令作用于选中的文字，没有选中时作用于整个编辑器。每条命令一次撤销。
- **美化 SQL**：用 `sqlformat` crate（MIT 或 Apache-2.0）。缩进按偏好设置的制表符宽度和“按下 Tab 键时插入空格”；“大写关键字”对应 `uppercase`，“短括号长度”对应 `max_inline_block`（括号内的文字不超过这个长度时留在一行）。PostgreSQL 用 `sqlformat` 的 PostgreSQL 方言（认识 `::` 和 `$1`），其余用通用方言。美化前后去掉空白的记号序列必须相同（关键字大小写除外），单元测试覆盖三种方言的引号、注释和 `$tag$` 字符串。
- **美化 SQL 选项**（356 × 143）：短括号长度（默认 50）、大写关键字（默认勾选）；按钮“默认”“保存”“取消”“美化”。“保存”只保存，“美化”保存后立即美化。选项存在 `settings.json`。
- **简化 SQL**：把字符串和引号标识符以外的连续空白压成一个空格，每条语句占一行；`--` 和 `#` 注释改写成 `/* … */`，以免吞掉后面的代码。
- **查找与替换**：⌘F 查找，⌥⌘F 查找和替换，⌘G、⇧⌘G 查找下一个、上一个（“编辑 > 查找”子菜单里同样有）。查找栏在编辑器顶部。第一行是模式下拉（查找 / 替换）、查找输入框、上一个、下一个、“完成”。替换模式才有第二行：替换输入框、“替换”、“全部替换”。模式下拉里还有正则表达式、大小写符合、整个字。递增搜索始终开着：边输入边高亮全部匹配，并选中光标之后的第一个；到文件末尾不回绕，与 Navicat 一致。查找输入框回车等于“下一个”；替换输入框回车等于“替换”（替换当前这一处并跳到下一个）。“替换”一次替换当前匹配并跳到下一个，“全部替换”一次撤销。正则表达式写错时查找框变红，不弹窗。“完成”或 Esc 关闭查找栏并清掉高亮。
- **剪贴板堆栈**：在编辑器里拷贝或剪切时，文字同时压进剪贴板堆栈。堆栈全应用共用，只在内存里，最多 10 项，后进先出，与栈顶相同的文字不重复压入。⇧⌘V（“编辑 > 从剪贴板堆栈粘贴”）粘贴栈顶；紧接着再按，用下一项替换刚粘贴的文字，到底后回到栈顶。中间有别的编辑或移动了光标，就重新从栈顶开始。
- **右键菜单**：剪切、拷贝、粘贴、从剪贴板堆栈粘贴、全选；运行已选择的、运行当前语句、解释已选择的；美化 SQL、注释 ▸、转换大小写 ▸；创建片段…（第 5 节）。没有选中文字时，和选区有关的项禁用。

## 4. 代码补全（F-QRY-002、F-PREF-006）

- **触发**：输入标识符字符或 `.` 时弹出；菜单关着时按 Esc 也会弹出。Tab 和回车插入选中项，上下方向键选择，Esc 关闭。偏好设置关掉“使用代码补全”，或文本超过高亮阈值时不弹出。
- **候选**：
  - 关键字和内置函数：按方言列出，放在 `navidog-db` 的方言里；
  - 数据库、模式、表、视图、函数、字段：来自代码补全信息（见下）；
  - 代码段：按名称匹配，选中后插入代码并开始占位符跳转（第 5 节）。
- **上下文**：`.` 前面是数据库或模式时，列出其中的表和视图；是表、视图或别名时，列出字段。别名在当前语句里按 `FROM`、`JOIN` 后面的“名称 [AS] 别名”查找。ponytail: 只看当前语句，不解析子查询的作用域；需要时再接语法树。
- **排序与显示**：不区分大小写。排序分三档：前缀、连续包含、跨字符（名称里按顺序出现输入的每个字符即可，中间可以隔着别的字符；间隔更短的在前）。例如 `mocfg` 匹配 `mount_cfgs`。同一档、同一间隔内按名称字母序。每项显示名称和说明，例如 `actor`“表”、`first_name`“字段 · varchar(45)”。gpui-kit 的补全浮层没有图标位，用说明文字代替 Navicat 的图标（偏差）。命中的字符涂蓝：前缀和连续包含涂成一段，跨字符涂各自对上的字（相邻的合成一段）。需要引号的名称插入时按方言加上。
- **代码补全信息**：每个连接的每个数据库（PostgreSQL 是每个模式）一份，包含表、视图、函数和全部字段。`navidog-db` 新增一个元数据查询一次取齐：

  | 方言 | 来源 |
  | --- | --- |
  | MySQL / MariaDB | `information_schema.TABLES`、`COLUMNS`、`ROUTINES`，按 `TABLE_SCHEMA` 过滤 |
  | PostgreSQL | `pg_class`、`pg_attribute` 加 `format_type`、`pg_proc`，按模式过滤 |
  | SQLite | `sqlite_schema` 加 `pragma_table_xinfo` |

  取到后缓存在内存里，同时写到该连接目录的 `.outline/<数据库>[/<模式>].json`（名称按第 7 节的规则编码；放在以 `.` 开头的目录里，数据库名开头的 `.` 会编成 `%2E`，不会和它撞名）。“自动更新代码补全的信息”开启时（默认），查询编辑器选中一个数据库或模式就重新取一次；关闭时用磁盘上的那份，需要时用“编辑 > 代码补全 > 更新代码补全的信息”手动更新。“更新代码补全的信息时包括系统对象”（默认关）开启后连同 `information_schema`、`mysql`、`sys`、`performance_schema`、`pg_catalog` 一起取，SQLite 没有系统对象。“清除代码补全的信息”删掉全部连接目录下的 `.outline` 和内存里的数据。信息窗格的标识符页用同一份数据（第 6 节）。
- **自动选择第一个建议项目**（默认开）：关掉后要先按方向键才能确认，回车和 Tab 照常换行和缩进（做法见第 1 节）。

## 5. 代码段（F-QRY-010、F-INFO-005）

- **存储**：`navidog-core` 的 `snippets` 模块，信息窗格和代码补全共用。预设的片段由我们自己编写（不复制 Navicat 的内容），编进程序，只读；自定义片段存在配置目录的 `snippets.json`。每个片段有名称、数据库类型（全部、MySQL、MariaDB、PostgreSQL、SQLite）、标签、备注和代码。
- **占位符**：代码里写成 `${文字}`。插入后选中第一个占位符，Tab 和 ⇧Tab 在占位符之间移动；走完最后一个、按 Esc 或把光标移出所有占位符就结束跳转。PostgreSQL 的 `$1`、`$$` 不带花括号，不受影响。
- **代码段页**（信息窗格，第 6 节）：顶部是标签筛选（“所有标签”和各个标签）和新建按钮 +，中间是片段列表（行高 37，32pt 图标加名称），底部是搜索框（匹配名称和代码）。右键菜单：预览、新建片段…、编辑片段…、复制片段…、删除片段；显示其他数据库类型的片段（默认勾选）、显示预设的片段（默认勾选）；刷新。“显示其他数据库类型的片段”关掉后，只列出当前查询编辑器的数据库类型和“全部”的片段。Navicat Cloud 相关的“解决冲突…”“复制片段到”“移动片段到”不做。
- **插入**：把片段从列表拖到编辑器，插在光标处；或在编辑器里输入片段名称，从补全菜单中选择。
- **查看和编辑**：双击片段弹出查看框（360 × 341）：名称、代码预览、“编辑”按钮（预设的片段没有）。编辑框（360 × 507）：名称、数据库类型、标签（选已有的或输入新的）、备注、代码（336 × 180 的 SQL 编辑器）；左下角“添加占位符”（把选中的文字变成占位符）和“移除占位符”，右下角“取消”“保存”。名称为空，或与同一数据库类型的片段重名时，“保存”禁用。
- **创建片段**：编辑器右键“创建片段…”打开编辑框，代码预先填入选中的文字；代码段页的 + 打开空的编辑框。Navicat 还能把选中的代码拖进代码段页，gpui-kit 的编辑器不能作为拖动源，不做（偏差）。

## 6. 信息窗格（F-INFO-004 ~ F-INFO-006）

- **预览**：选中已保存的查询时出现，只读显示它的 SQL，与 DDL 页同一套高亮，⌘F 查找。
- **代码段、标识符**：查询编辑器选项卡激活时，标题栏多出这两个按钮，默认停在代码段。离开查询编辑器后这两个按钮消失，回到原来的页。
- **标识符**：顶部是搜索框（栏高 30，框高 22），下面是当前查询编辑器所选数据库或模式的树：表和视图，展开后是字段，字段旁显示类型。数据来自代码补全信息，还没取到时显示“正在加载…”。双击或拖到编辑器，把名称（需要时加引号）插到光标处。
- **跨 crate 的接线**：信息窗格在 `navidog-navigator`，编辑器在 `navidog-query`，两者不互相依赖。双击时派发 `navidog_core::actions::InsertText`，外壳把它转给当前激活的查询编辑器；拖动的载荷也是这个类型。代码段的读写在 `navidog-core`，代码补全信息在 `navidog-db`（要用驱动）。
- 弹出为新窗口的查询编辑器没有信息窗格，也就没有代码段和标识符页；Navicat 在编辑器窗口右侧另放一栏（偏差）。

## 7. 保存查询（F-QRY-011）

- **位置**：`profiles/<连接 ID>/<数据库>/<名称>.sql`；PostgreSQL 是 `profiles/<连接 ID>/<数据库>/<模式>/<名称>.sql`。目录名里的 `/`、`\`、`:`、`%` 和开头的 `.` 做百分号编码。文件是 UTF-8 文本。读写放在 `navidog-core` 的 `queries` 模块，写入时照例先写临时文件再替换。
- **新建**：⌘Y、主工具栏“新建查询”、导航树和对象选项卡的“新建查询”。连接、数据库和模式取自工作区选择；什么都没选时三者为空，运行前要先在工具栏里选。
- **保存**：⌘S。无标题的查询先弹出“查询名称”输入框，存到工具栏所选的位置；没有选连接时改为“另存为外部文件”。名称为空、含 `/` 或 `:`、以 `.` 开头，或与同一位置的查询重名（不区分大小写）时，提示“查询名称无效或已存在。”。⇧⌘S“另存为”换一个名称存到当前位置，选项卡随后绑定到新查询。
- **外部文件**：“文件 > 打开外部文件 > 查询…”打开任意 `.sql` 文件，选项卡标题是文件名，⌘S 写回原文件；“文件 > 另存为外部文件…”用系统存储面板；打开的是外部文件时，“文件 > 另存为 Navicat 查询…”把它存进当前位置。
- **外部修改**：选项卡重新激活时比较文件的修改时间，变了就问“查询“名称”已在外部修改。是否重新加载？”。编辑器里也有未保存的修改时，重新加载会丢掉它们，所以默认按钮是“取消”。
- **对象分类“查询”**：新增 `ObjectKind::Query`。导航树和对象选项卡里，每个数据库（PostgreSQL 是每个模式）下都有“查询”分类，列出该位置的 `.sql` 文件（不带扩展名，按名称排序），由 `navidog_core::queries` 列出，不经过驱动。详细信息视图的列：名称、修改日期、大小。对象工具栏：打开查询、设计查询、新建查询、删除查询。“设计查询”和双击都在查询编辑器中打开；“打开查询”打开后立即运行（与 Navicat 并排核对）。右键菜单另有重命名（原地编辑）、复制查询（副本叫 `名称_copy1`，依次递增）、使用外部编辑器打开（用系统默认打开 `.sql` 的应用；自定义编辑器路径随 M9 的“环境”偏好设置加入）、在 Finder 中显示。删除前确认，删除就是删掉文件。外壳的 `editors.rs` 把 `ObjectKind::Query` 交给查询编辑器打开。
- **信息窗格“常规”页**：查询显示名称、位置（文件路径）、大小、修改日期。

## 8. 自动恢复（F-APP-016、F-PREF-008）

- 按偏好设置的间隔（默认每 30 秒），把有未保存修改的查询编辑器（含无标题的）写到配置目录的 `autosave/<编辑器 ID>.json`：标题、连接、数据库、模式、对应的查询或外部文件路径、文本、保存时间。保存成功、选“不保存”关闭时删除对应的文件。间隔设为“永不”时不再写入，已有的文件保留。
- **正常退出**：有未保存修改的编辑器再写一次，并标记“退出时保存”；没有修改的删除文件。下次启动时这些选项卡随窗口布局回来（无标题和外部文件的选项卡按编辑器 ID 恢复），带着未保存的文本，不弹窗。Navicat 退出时逐个询问是否保存（偏差）。
- **异常退出**：启动时 `autosave/` 里还有没标记的文件（或标记了但布局里没有对应选项卡），弹出“恢复”对话框（870 × 600）：“找到自动保存的文件。你要将它们恢复吗？”。表格每行一个复选框（默认全选），列是保存时间和名称（含位置）；下方是“全选”“取消全选”，右下是“取消”“好”。“好”把勾选的放回：布局里已有同一编辑器（同 ID，或同一个已保存的查询）就写进它，否则在新的查询编辑器中打开，对应的查询还在时绑定到它，否则是无标题；文本标为未保存。没勾选的文件删除。“取消”什么都不删，下次启动再问。
- M3 只自动保存查询；偏好设置里“模型”“BI 工作区”两行随 M7、M10 加入。

## 11. 偏差

- 补全浮层没有图标，用说明文字区分对象类型。
- 拖进编辑器的文字插在光标处，不在落点；不能从编辑器把选中的代码拖进代码段页。
- 弹出窗口里没有代码段和标识符页。
- 编辑器字体只改字号，字体系族固定为 `font.mono_family`。
- 自定义代码段存在一个 `snippets.json` 里，不是每个片段一个 `.nsnippet` 文件，不与 Navicat 互通。
- “使用外部编辑器打开”用系统默认应用，自定义编辑器路径随 M9 加入。
- Navicat 右键菜单里的“含引号复制”M3 不做：它的格式列表要与 Navicat 并排实测后再定。
- 关掉“自动选择第一个建议项目”后，补全菜单的第一项仍画成选中的样子，只是回车和 Tab 不再确认它（第 1 节）。
- 选项卡标题悬停显示拼好的标题全文，不另列文件路径。
- “恢复”是主窗口里的对话框，不是独立窗口（与 M1 的连接表单相同）；正常退出不询问是否保存（第 8 节）。
- 片段编辑框的“添加占位符”“移除占位符”是带提示的图标按钮：360 宽的对话框放不下四个文字按钮。
- 查找栏的正则表达式、大小写符合、整个字在模式按钮的菜单里，不单独占一排按钮。
