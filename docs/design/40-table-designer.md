# M4 规格：表设计器

覆盖 F-DSG-001、002、003、004、007、009、010。其他对象设计器、排除约束、触发器和分区的专门表单另开规格，不在本次实现范围。

## 1. 入口与布局

对象工具栏的“新建”“设计”、导航树表的右键菜单打开设计器；双击表仍打开数据查看器。新表取当前数据库/模式。没有已打开的数据库时提示先选择数据库。新表与已有表均是对象窗格中的独立选项卡，接入 tabs 生命周期、关闭守卫和布局持久化。

工具栏：保存（⌘S）、添加字段（⌘+）、删除字段（⌘-）、复制字段（⌘D）、上移/下移。保存先打开只读 SQL 预览；预览不改变数据库。SQL 预览页去掉“保存”，改为带图标的“执行”，点执行才写入；添加、删除等其余按钮仍在。离开预览页后恢复“保存”。执行期间禁用编辑和重复提交，失败保留草稿及错误。关闭未保存草稿时提供取消/不保存，保存通过工具栏完成。

主区采用 Navicat 的上下结构，不采用左右字段列表/SQL 输入框。页签为字段、索引、外键、检查、选项、SQL 预览；SQL 仅在预览或明确的高级定义入口显示，不代替正常表单。

字段页上方为可水平滚动的多列网格：名称、类型、长度、小数点、不是 null、虚拟、键、注释。选择字段后下方属性区显示默认值、排序规则；字符字段显示字符集（MySQL），数值字段显示自动递增与无符号（按方言），生成列显示表达式和存储方式。名称、类型、长度、小数点和注释可通过单元格进入编辑；复选属性直接切换；⇧⌘K 设置主键。所有修改只改草稿，SQL 预览和执行仍分开。

索引页为名称、字段/表达式、类型、方法、注释的列表和编辑表单；外键页为名称、本表字段、引用模式/表/字段、删除时/更新时的表单；检查页为名称和表达式。编辑已有条目不丢弃不支持的属性：可安全解析的片段结构化编辑，不能安全解析时保留原定义并显示高级入口，禁止猜测替换。字段列表和定义列表按稳定 ID/源条目定位，切换页或选择不丢草稿。

字段属性区复用 Navicat nib 的 300pt 输入宽度、22pt 行高、8pt 行间距；字段网格表头 23pt，字段列宽及属性区默认高度暂定，集中在 tokens.rs 并在 02 登记来源。区域使用可拖动分隔条，上部吸收剩余高度，窄窗通过横向滚动访问所有列，不压缩或隐藏字段。来源：本地 `TableDesignFieldModule_mysql`、`TableDesignFieldsModule_sqlite`、`TableDesignIndexesModule_mysql`、`TableDesignForeignKeysModule_mysql` 的导出视图树。未取得运行时屏幕截图的尺寸仍明确标为暂定。

新表名为空，初始字段 `id INTEGER NOT NULL`，约束 `PRIMARY KEY (id)`；默认不执行 SQL。

## 2. 驱动与迁移

领域草稿和方言 SQL 计划在 navidog-db；UI 在独立 navidog-designer，不依赖其他 feature。读取原始 CREATE TABLE 定义，分离字段、表约束、表选项和独立索引/注释语句。保留未编辑片段，未知语法不能悄悄降级。

- MySQL/MariaDB：差异生成 ALTER TABLE；字段按原名称识别重命名，使用完整定义 CHANGE COLUMN，保留未改动定义与表选项。约束和索引改动须能识别名称，否则阻止保存，提示原因。DDL 隐式提交，执行失败后标记需要重新加载，禁止对部分成功的状态盲目重试。
- PostgreSQL：字段添加/删除/重命名，支持普通字段类型、NULL 和 DEFAULT 差异；无法安全分解的字段属性变化明确拒绝。约束和索引按名称变更。事务内执行，失败回滚。
- SQLite：在独立会话关闭外键检查，BEGIN IMMEDIATE 内把旧表改名为 `_表_old_日期`（当天已占用则 `_1`、`_2`）并留下，用原名创建新表，按原字段名拷回保留字段，再把索引和触发器移到新表。不删除改名后的旧表。foreign_key_check 成功后提交，恢复原外键开关。失败回滚且保留原表。新增列取默认值；不能保留的隐式 rowid 语义、生成列等必须明确拒绝或专门处理，不能默默丢弃。临时表名称冲突时失败而非覆盖。

执行前在同一会话重新读取结构，与草稿基线比较，外部变化时拒绝执行并要求重新加载；成功后重新读取并刷新导航目录。新建表由数据库的同名对象检查保护，禁止 CREATE IF NOT EXISTS 掩盖冲突。

## 3. 安全与状态

字段名和表名统一 quote_ident。SQL 定义是用户明确输入的 SQL 片段；检查引号/括号闭合，拒绝片段外的分号和多条语句。SQL 预览逐条列出实际执行语句。结构删除会显示在预览里。数据库错误作为正文显示，不只写日志。未保存草稿随布局序列化，恢复不执行 SQL。

## 5. 首版边界与后续

- 原首版的 SQL 输入主界面被撤回，改为字段网格及结构化索引、外键和检查表单；高级 SQL 仅供无法结构化表达的定义使用。
- SQLite 主数据库支持完整常见表的事务重建，保留索引、触发器、入站外键、视图、隐藏 rowid 和 AUTOINCREMENT 序列高水位；纯索引变更直接执行。生成列表的重建、附加数据库明确拒绝。字段重命名单独保存，由 SQLite 原生重写依赖。删除字段先在保存点内用原生 DROP COLUMN 检查依赖，回滚预检后再迁移；有依赖时要求先移除依赖。
- PostgreSQL 不支持现有列的物理重排，也不猜测生成列、identity、collation 等特殊属性的 ALTER。加载额外读取这些标志及列注释，保留属性并纳入外部变更指纹。常用表选项修改已由第 8 节补齐，表和字段注释修改见第 9 节。
- MySQL DDL 可能部分成功；失败必须重新加载。先检查结构再执行不能消除 MySQL DDL 的并发变更窗口，保存期间应避免在别的客户端同时改同一张表。
- 本次不修改其他 M4 对象设计器的状态，不把 Navicat 并排视觉校准视为已完成。

## 7. 外键引用对象级联选择

沿用现有 300pt 表单行与输入框旁的选择菜单，不新增尺寸。被引用模式（MySQL 为数据库、PostgreSQL 为当前数据库内模式）、表、字段从当前连接元数据读取；SQLite 仅当前数据库，不显示模式选择。字段允许按顺序多选，保留手工输入以支持尚未创建的对象。标识符由方言引用，字段数不一致时阻止 SQL 预览。

用户更换引用模式时清空引用表和字段，更换表时清空引用字段，避免携带旧对象的字段；加载已有外键只读候选，不改定义。级联读取异步执行，过期结果不得覆盖当前对象；读取中禁用候选菜单，显示加载状态，失败显示原因及重试入口，仍保留草稿。自引用候选以当前草稿字段为准。类型/唯一键等方言兼容性由数据库执行检查，失败保留草稿，不用字符串类型比较冒充完整兼容性验证。

## 8. 表选项与方言属性

选项页采用现有 FormRow 的 300pt 输入宽度、22pt 控件和 8pt 间距，纵向滚动；沿用输入框旁的选择菜单及复选框。只修改草稿，保存仍先预览再执行。空输入代表未显式指定；已有 MySQL 参数清空时不能假装服务器会恢复默认，无法生成明确重置语句时阻止预览。未知/重复选项保留原文，不能安全拆分时禁用结构化编辑并提供高级入口。

- MySQL/MariaDB：引擎、字符集、排序规则、自增值、行格式、平均行长度、最大/最小行数、键块大小、统计信息自动重算/持久化/采样页数、校验和、延迟键写、打包键、插入方法、连接、数据/索引目录、表空间、压缩、加密和表注释。枚举菜单提供常用合法值，版本/引擎能力由服务器验证；不猜测其他引擎私有属性。
- PostgreSQL：拥有者、表空间、继承（有序、可带模式的引用表列表）、填充因子、autovacuum_enabled 和 UNLOGGED。读取 pg_class/pg_inherits，存储参数、拥有者和持久性纳入并发指纹；修改生成 OWNER TO、SET TABLESPACE、INHERIT/NO INHERIT、SET/RESET、SET LOGGED/UNLOGGED，和其他表结构变更放在同一事务中。高级存储参数保留，不因编辑填充因子而丢失。不提供新版本已删除的 OIDS。
- SQLite：WITHOUT ROWID 与 STRICT；启用 WITHOUT ROWID 会丢弃隐式 rowid，普通表与 WITHOUT ROWID 的相互转换明确拒绝（创建新表允许）；STRICT 修改沿用事务重建，类型/现有数据不兼容时回滚。
- 字段补充 MySQL/MariaDB 的 ON UPDATE 表达式与 ZEROFILL；PostgreSQL identity 模式（无/ALWAYS/BY DEFAULT），编辑已有 identity 仅支持模式切换，复杂 sequence 选项保持原样，不猜测降级。

参考本地 TableDesignOptionsModule_mysql/pgsql/sqlite 导出，以及 PostgreSQL 16 ALTER TABLE、MySQL 8.4 CREATE TABLE 与 SQLite STRICT 官方语法。排除约束、分区和引擎私有选项仍在各自规格范围，不以本节宣称完整 M4 验收。

## 9. PostgreSQL 表与字段注释（2026-10-20）

字段注释沿用八列网格的“注释”单元格与现有输入框；表注释放在选项页的“注释”行，复用已有 FormRow 尺寸。加载表和字段现有注释，输入只修改草稿；清空表示移除注释。MySQL 注释继续由字段定义和表选项处理，SQLite 不显示无效注释编辑器。

PG 表注释和每个字段注释独立保存，旧版补充 SQL 中的 COMMENT ON TABLE/COLUMN 在加载旧草稿时迁移，不能按索引删除处理。无法安全识别、重复或指向其他对象的旧注释保留原文并阻止保存，不能猜测归属。字段注释按 original 身份跟随重命名；新字段可带注释，删除字段不再向旧字段发送注释。注释未改变时不生成重复语句。

SQL 计划先完成字段/约束/索引与选项变更，再执行 COMMENT ON TABLE/COLUMN，最后才转移拥有者。空字符串生成 IS NULL；名称按方言引用，文本使用显式 E 字符串转义，支持中文、引号、反斜杠、换行和 SQL 标点，拒绝 NUL。注释与表结构在同一事务内保存、失败回滚；外部注释变化也应触发并发结构检查。预览和恢复草稿不执行 SQL。

语法依据：[PostgreSQL 16 COMMENT](https://www.postgresql.org/docs/16/sql-comment.html)。不在本次扩展索引/约束注释编辑或修改其他设计器。

## 10. Review 补充：身份与重新加载（2026-10-20）

同表的数据查看器与设计器各有独立身份；重复设计激活已有设计页或其弹出窗口。设计页保存对象引用，纳入收藏、启动项与断线关闭；重命名保存成功后更新引用。表查看器的“表 > 设计表”和 ⌘D 设计当前表。

未改动的新建表、未改动的已有表与首次加载失败的设计页关闭不询问；实际编辑后仍有关闭守卫。保存或重新加载成功后，清空输入错误及单元格编辑状态，按重新读取的条目顺序重建表单，防止旧表单写入其他条目。SQL 预览页禁用删除。字段选择按标识符身份切换，带引号和未带引号的相同字段不重复。
