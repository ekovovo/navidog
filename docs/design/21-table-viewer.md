# M2 规格：表查看器与结果网格

覆盖功能：F-DATA-001 ~ F-DATA-014、F-OBJ-008（打开表）、F-INFO-007。结果网格将来会被查询结果（M3）复用，所以放在单独的 crate `navidog-grid` 中。

行为来源：`data_viewer.html`、`data_rdbms.html`、`data_edit.html`、`data_filter.html`、`data_filter_wizard.html`、`data_sort_find.html`、`data_format.html`、`data_navigation_bar.html`、`data_raw.html`、`data_assistant_editors.html`、`data_field_comment.html`。

尺寸来源：`TableViewViewController`、`GridViewController`、`FilterAndSortManager`、`FormViewController`。

## 1. 技术验证：结果网格（M2 开工后先做，结论写回本节）

`gpui-component` 的 `DataTable` 已经提供：
- 行、列两个方向的虚拟化；
- 左侧固定列；
- 列宽调整、列移动；
- 由 delegate 实现的排序和右键菜单；
- 无限加载（`has_more`、`load_more`）。

它缺少 Navicat 网格的几项核心能力：

| 需求 | 在外层实现的方式 |
| --- | --- |
| 矩形区域选择，⇧ 和 ⌘ 扩展选择 | 选择模型由 `GridState` 自己维护；`render_td` 根据它绘制选中背景；单元格上的 `on_mouse_down`、`on_mouse_move` 实现拖拽选择；`DataTable` 自带的单格选择只用作键盘焦点 |
| ⇧ + 方向键扩展选择 | 网格外层加 `key_context("ResultGrid")` 和 Action：方向键在焦点移动后同步选择，⇧ + 方向键修改选区 |
| 就地编辑 | 双击或回车时，在 `render_td` 中把正在编辑的单元格渲染成 `Input`；Esc 取消；Tab 和回车提交并移到下一格 |
| 修改标记 | 修改过的单元格、新增行、待删除行分别用不同背景表示（颜色按 Navicat 实测，登记进 token 表） |
| 行号列 | 第 0 列作为固定列，宽 `grid.row_number_width` |

判定规则：在 10 万行、20 列的数据上，矩形选择、键盘扩选、就地编辑都能工作，并且滚动时单帧不超过 8.3ms，就采用 `DataTable` 加外层补充；否则基于 `gpui-base` 的 `Table` 原语和 `VirtualList` 自建 `ResultGrid`。不管选哪种，对外接口都一样（第 2 节），选择不影响上层代码。

**结论：采用 `DataTable` 加外层补充。** 验证程序是 `cargo run --release -p navidog-grid --example spike`（1440 × 900 的 headless Metal 窗口，10 万行 × 20 列，每次滚动后测一帧的布局与绘制时间，各 300 帧）。

初次测量时数据行是 20pt：

| 场景 | 平均 | p95 | 最大 | 超过 8.3ms 的帧 |
| --- | --- | --- | --- | --- |
| 逐行滚动（每帧 3 行） | 6.1ms | 6.9ms | 29.6ms | 5 / 300 |
| 跳跃滚动（每帧 997 行） | 6.1ms | 7.0ms | 11.2ms | 2 / 300 |

显示字段类型时，数据行曾和表头共用高度，被抬到 34pt，900px 高的窗口大约只画 25 条数据。表头拆开之后数据行回到 20pt，一屏大约 43 条。2026-10-09 在 20pt 数据行、34pt 表头上重测（已去掉用来挡住悬停的格子层）。当时验证程序的列没有类型，release 用的是 `opt-level = "s"`：

| 场景 | 平均 | p95 | 最大 | 超过 8.3ms 的帧 |
| --- | --- | --- | --- | --- |
| 逐行滚动（每帧 3 行） | 9.8ms | 10.6ms | 13.3ms | 300 / 300 |
| 跳跃滚动（每帧 997 行） | 10.1ms | 11.0ms | 17.6ms | 300 / 300 |

2026-10-10 验证程序改用真实类型（`int`、`varchar(45)`、`datetime`、`decimal(10,2)`、`text` 轮流），表头画类型行，数字列右对齐；单元格绘制不再每帧复制字符串和归类类型。同一台机器上只改 `opt-level`：

| 场景 | opt-level | 平均 | p95 | 最大 | 超过 8.3ms 的帧 |
| --- | --- | --- | --- | --- | --- |
| 逐行滚动（每帧 3 行） | `"s"` | 10.4ms | 11.5ms | 13.6ms | 300 / 300 |
| 跳跃滚动（每帧 997 行） | `"s"` | 10.6ms | 11.6ms | 24.5ms | 300 / 300 |
| 逐行滚动（每帧 3 行） | 3 | 8.5ms | 9.5ms | 19.6ms | 171 / 300 |
| 跳跃滚动（每帧 997 行） | 3 | 8.6ms | 9.8ms | 19.9ms | 180 / 300 |

- release 用 `opt-level = "s"`（体积优先）。上表是这个选择的滚动代价：`"s"` 比默认的 3 慢约 20%，不把 opt-level 改回 3。相对初次的 6.1ms 仍然更慢：可见行更多，表头要画类型行，单元格也更重。8.3ms 的预算平均略超、约一半的帧超时，仍继续用 `DataTable`。下一步可以把表查看器的工具栏和底部栏拆成单独缓存的子视图，滚动时只重绘网格。
- 偶发的超时帧来自首次排版没见过的文本（每行内容都不同），自建网格同样要经过这一步，所以不影响结论。debug 构建平均约 10.8ms。
- 矩形选择、⇧ + 方向键扩选、就地编辑、复制都由 `crates/navidog-grid/tests/grid.rs` 通过真实的点击和按键验证。
- 实现中与上表设想不同的两点：
  - `DataTable` 只在按下和抬起是同一格时发出 `SelectCell`，所以选区在单元格的 `on_mouse_down` 中更新，拖拽通过 `on_mouse_move` 扩展。只有这次按下发生在单元格上才扩展；拖动表头经过单元格不改选区；
  - 行号列是 delegate 的第 0 列（固定在左侧），显示当前行、已修改、新增和待删除的标记，不显示行号，与 Navicat 一致。
- 已知差异：每个可排序列的表头都会显示 `DataTable` 的默认排序图标，而 Navicat 只在已排序的列上显示。

## 2. `navidog-grid` 对外接口

```rust
pub struct GridData {
    pub columns: Vec<GridColumn>,      // 名称、类型、是否主键、是否可为空、注释
    pub rows: Vec<Vec<CellValue>>,     // 当前页
    pub total_rows: Option<u64>,       // COUNT(*)，异步获得
}

pub enum CellValue { Null, Text(SharedString), Binary(usize /* 字节数 */) }

pub struct GridState {
    // 数据、选择、编辑中的单元格、修改集合、列宽、隐藏列、行高
}

pub enum GridEvent {
    SelectionChanged,
    CommitRequested(ChangeSet),   // 离开已修改的行、点击“应用”、⌘S
    LoadPage(u64),
}

pub struct ChangeSet {
    pub updates: Vec<RowUpdate>,  // 定位行的主键值（没有主键时用整行旧值）加上修改过的列
    pub inserts: Vec<Vec<CellValue>>,
    pub deletes: Vec<RowKey>,
}
```

`ChangeSet` 转成 SQL 的工作由 `navidog-db` 中各方言的 `Dialect::render_changes` 完成，并配有单元测试覆盖：标识符引用、NULL 值、二进制值、没有主键的表。

## 3. 表查看器布局

```
┌─────────────────────────────────────────────────────────────┐
│ 工具栏：开始事务 | 文本 | 筛选与排序 | 导入 | 导出 | 生成数据 │
├─────────────────────────────────────────────────────────────┤
│ 筛选与排序窗格（⌘⇧F 显示或隐藏）                              │
├────┬────────────────────────────────────────────────────────┤
│ 行号│ 网格（显示类型时表头高 34，数据行高 20）                │
│ 20 │                                                         │
├────┴────────────────────────────────────────────────────────┤
│ 底部栏（高 28）：+ − ✓ ✗ ⟳ 停止 | SQL 预览 | ⏮ ◀ [页] ▶ ⏭ | 限制 [1000] 条记录每页 │
└─────────────────────────────────────────────────────────────┘
```

- **网格视图和表单视图**：网格视图之外还有表单视图（`FormViewController`），一次编辑一条记录，可以随时切换。
- **横向滚动**：查看器把网格限制在选项卡宽度内（`min_w_0`），列超出时由 `DataTable` 的横向滚动条滚动。滚动条在指针位于滚动区域时出现，可以拖动；指针不在网格上时不画。触控板横向滑动同样滚动。不要把选项卡撑宽后被停靠区裁掉。悬停时整行换成 `table.hover.background`，奇数行、偶数行和最后一列右边的空白一起变，和 DataTable 一样。点最后一列右边的空白选中整行，和点行标记列一样。选中单元格后，选区碰到的每一行在不悬停时换成 `color.grid_row_selected`（画在行上，盖住底纹，空白处也是这个颜色）。选中的格子仍用选中色。正在编辑的那一格保持透明，让选中行的底色透出来，只加一圈 `color.accent` 边框；文字选区用 `color.text_selection`。数据行下面多留一行空白（不可编辑、不可选中，没有竖向分割线，悬停时也不变色），横向滚动条盖住的是这一行，最后一条记录可以点到。
- **单元格**：数字类型右对齐，其它类型左对齐。表头仍左对齐。就地编辑时字号与网格相同，这一格用纸色（不用选中底色，否则看不清文字选区），单元格外加一圈 `color.accent` 边框。正在编辑时，在编辑框里拖拽只选中文字，不会把选区扩到别的单元格。只有从单元格按下的拖动才扩展选区；拖动表头经过单元格时不改变选区。
- **表头**：默认在同一个单元格里显示字段名，下面一行是类型图标和类型名。数字蓝、字符串绿、日期时间橙、布尔青绿、二进制黄、JSON 紫，其余灰。排序图标在单元格右侧，和字段名之间不画竖线。右键可以关掉类型、复制字段名称。注释开着时跟在类型后面，类型关掉时跟在字段名后面。显示类型时表头高是 `grid.type_header.height`，数据行仍用设置的行高。关掉类型后表头高度回到行高。拖动表头可以调整列顺序（行标记列不动）。列顺序和冻结只在当前表查看器里保留，翻页不会回到服务器的列序；关掉查看器后不写入 settings.json。
- **列宽**：打开表时，没有拖过的列按列名（另加排序图标的宽度）和当前已加载数据估算。单元格用网格画出的文本，换行折成空格，每格最多 64 个字符；只看前 64 行。ASCII 约 0.62em，其它字符约 1em，再加上内边距，夹在 56–460 px。类型行不参与。拖过的列按表记在该连接目录的 `.column-widths.json`，下次打开仍用记下的宽度；只拖动一列不会把同表其它列一起记下。翻页时，没拖过的列按新页重算。双击列顶右边框把这一列再调成适合内容（`data_format.html`）还没做：拖动手柄在 `DataTable` 内部。
- **冻结**：列菜单有三项。“冻结到此列”不搬家，把当前显示顺序从左侧到这一列标成冻结。“冻结列”把这一列插到已冻结列的后面再冻结；已经冻结则不变。“解除所有冻结列”取消冻结，并把因为冻结而搬家的列放回拖拽之后的位置。没有冻结列时，“解除所有冻结列”禁用。“恢复默认顺序”把列放回服务器返回的顺序，并取消冻结；已经是这个顺序时禁用。冻结列之间、未冻结列之间可以拖动重排，不能拖过冻结边界。
- **新增行**：没填的单元格显示 `(Default)`（与 Navicat 一样用这串英文，不进 SQL）。空表也可以新增。整行用 `color.grid_inserted`。列与列之间用 `color.grid_line`。
- **SQL 预览**：只读的 SQL 编辑器（`tree-sitter-sql`），和 DDL 页同一套高亮。
- **底部状态文字**：最近执行的 SQL、批量提交的多条语句或错误信息只占底部栏剩余宽度。显示时把换行折成空格，保持单行并在末尾省略；悬停显示保留换行的完整原文。底部栏保持 28pt 高，不挤出记录数、分页和每页条数控件。
- **单元格编辑器**：显示在网格下方。拖动它和网格之间的分隔条可以调整高度，默认高度不变；只在当前表查看器里记住，关掉查看器后回到默认。缩在选项卡里，不盖住底部栏；文字在编辑区内部滚动。文本、十六进制（这段文本的 UTF-8 字节，写回必须仍是合法 UTF-8）、网页（只显示 HTML 源码，不在浏览器里渲染）、JSON（可格式化，并用 `tree-sitter-json` 高亮）、枚举和集合（仅当类型字符串本身列出取值，如 `enum('a','b')`、`set('a','b')`）。图像可以加载、预览、保存到磁盘和清除；二进制图像只预览，不写入单元格，因为网格只保存文本。没有语法高亮的语言菜单，也不在信息窗格里再放一份。
- **标题**：`表名 @数据库 (连接名)`，例如 `actor @sakila (本地)`。PostgreSQL 的模式不进标题。悬停显示全文。
- **筛选与排序**：工具栏一个按钮“筛选与排序”（⌘⇧F），打开或关上同一块窗格。不另设一个效果相同的“排序”按钮。

## 4. 数据加载

- 打开表时执行 `SELECT * FROM <表> [WHERE …] [ORDER BY …] LIMIT <每页> OFFSET <偏移>`，同时另起一个查询执行 `COUNT(*)`，显示在底部栏里。
- 每页的记录数默认是 1000（偏好设置的“记录”页，F-PREF-005），可在底部栏修改，也可以取消“限制”，一次加载全部。
- 加载过程中，“停止”按钮调用会话的 `cancel_handle`。底部栏的刷新按钮同时旋转，至少半圈；加载比半圈更快时也转完再停。
- 表查看器为自己开一个独立的会话，不和导航树的元数据会话共用，避免长时间查询阻塞元数据浏览。

## 5. 编辑与事务

- **提交时机**：离开已修改的行、点击 ✓ 或按 ⌘S 时提交；点击 ✗ 放弃修改。翻页、点表头排序、应用筛选、快速筛选、改每页条数、刷新、切换 ROWID 之前也先提交，提交成功后再加载；提交失败时留在原来的行上，修改保留。提交或加载进行中网格不能编辑（不能改单元格、增删行、粘贴、替换，“放弃修改”也禁用），再按 ⌘S 或隐藏列不会发出第二次提交；否则提交成功后的重新加载会丢掉这期间的编辑。提交和翻页之前，正在编辑的那一格先写进修改。
- **未开启事务时**：每次提交独立执行，整批在一个事务里，失败时全部回滚。提交失败时弹出数据库的错误信息，修改保持未提交状态。
- **开启事务后**：工具栏显示“提交”和“回滚”；每批修改用保存点包住，失败时只撤销这一批，事务里之前的修改不受影响。偏好设置里可以设为自动开始事务，打开表时先加载首页，再开始事务。
- **关闭选项卡**：有未提交的修改或事务还没结束时，选项卡标题末尾显示 ●（gpui-kit 的关闭按钮这时隐藏），⌘W、右键菜单的关闭、点 ● 都先询问：“取消”保留选项卡（Esc 同），“放弃”丢掉修改并关闭（关闭会话即回滚事务），“提交”提交修改并结束事务后关闭（回车同）。提交失败时选项卡和修改都留下，弹出数据库的错误。关闭连接时仍直接关掉选项卡，不另询问。
- **定位不到行**：UPDATE 或 DELETE 没有匹配到任何行时，整批回滚，提示“没有匹配的行”，修改保留。MySQL 的 UPDATE 不做这项检查，因为它报告的是实际改变的行数，改成相同的值也是 0。
- **日期时间选择器**：日期、时间、日期时间列双击打开（`NAVDateTimePicker`，317 × 247）。输入框从单元格原文开始，不改直接确定就原样写回，负数或超过 23 小时的 MySQL `TIME` 也不变。点选日期时，秒后面的小数和时区（如 `.5+05:30`）原样保留。
- **无主键的表**：用整行的旧值定位，MySQL 加上 `LIMIT 1`；表查看器底部栏在记录数旁边提示“该表没有主键，可能影响多行”。
- **记录偏好**（F-PREF-005）：“修改后同步记录”默认开启，提交成功后重新加载当前页，生成列会更新。关掉之后不重新查询，已提交的修改留在网格里；没填写的新行不保留。未提交时未填的列显示 `(Default)`。只有服务器知道存下的值时仍会重新加载：新行有没填的列（默认值、自增主键），或某个值按 SQL 表达式写入；否则这些行显示的值不对，之后也定位不到。隐藏列时如果还有未提交的修改，仍会重新加载，以便投影和服务器一致。“点击以触发编辑”默认关闭，单击只选中，双击或回车才编辑；开启后单击数据单元格开始编辑，离开脏行触发提交时这一下只选中。网格字号在取消“使用默认字体”后生效，只改大小（8–72），字体系族仍是界面默认字体。行底纹为无、交替行（默认，沿用网格条纹）或每三行（数据行着色，表格下方的空白行不着色）。
- **原始数据模式**（F-DATA-010）：“查看”菜单和表查看器工具栏切换。开启后，字符串列的值在网格里显示为带引号的 SQL 字面量（`PENELOPE` 显示为 `'PENELOPE'`，引号按方言转义）；数字等其它类型不加引号。之后输入的非空文本按 SQL 表达式写入（如 `NOW()`、`UPPER('a')`），就地编辑、粘贴、表单视图都是如此；外键选择和单元格编辑器写入的是值本身，仍按字面量。复制按网格显示的文本，字符串带引号，在原始数据模式下粘贴回去得到同样的值。用来定位行的旧值仍是字面量。关闭后恢复不带引号的显示，一切按字符串字面量处理。已经输入的表达式保持当时的写法。
- **外键数据选择**（F-DATA-012）：右键菜单在外键列上提供。引用列来自目录查询（MySQL `KEY_COLUMN_USAGE`、PostgreSQL `pg_constraint`、SQLite `pragma_foreign_key_list`），不猜测列名。对话框列出被引用列的值，默认 1000 条，可筛选或一次取全部；单击写入当前单元格。同一列有多条外键时用第一条。不显示被引用表的其他列。

## 6. 筛选与排序

- **打开**：文本模式聚焦 WHERE 输入框；可视化模式聚焦第一条条件的值，没有条件则不移动焦点。关掉窗格时，若焦点在这块窗格里，焦点回到网格（表单视图回到查看器本身），⌘⇧F 才能再次打开。右键快速筛选不移动焦点。
- **可视化条件**：每条包含字段、运算符和值，可以取反，条件之间选 and 或 or。运算符照 `data_filter_wizard.html` 的完整列表实现（MongoDB 专有的“存在 / 字段类型”除外）。括号把当前全部条件包成一组，可以再对这一组取反；不能嵌套多层括号。
- **“文本”模式**：直接编辑 WHERE 子句；从可视化条件切换到文本时自动生成对应的文本，反向切换时如果解析失败，就保留文本模式。只有创建工具自己写出的 SQL（以及不带引号的简单字段名）能解析回来。“在列表”的值用逗号分隔，值本身不含逗号；带逗号的值解析时留在文本模式。
- **生成的 SQL**：值一律写成字符串字面量（`= '007'`），由数据库换成列的类型；裸数字在 PostgreSQL 的文本列上会报错，在 MySQL 里会让 `name = 0` 匹配所有非数字字符串。PostgreSQL 的包含、开头是、结尾是写成 `"列"::text LIKE …`，数字和日期列也能用；外键选择的搜索同样如此。“自定义”条件外面加一层括号，里面的 OR 不会和其他条件重新组合。
- **右键菜单快速筛选**：字段 = 值、字段 != 值、字段包含值；空单元格是“是 null”。文本模式下追加到现有 WHERE 之后。
- **排序**：可以多字段排序，用上移和下移调整顺序；点击表头切换升序、降序、不排序，并替换已有的排序。排序条件生成 ORDER BY，交给服务器执行。
- **查找**：工具栏“查找”、菜单“编辑 > 查找”（查找、替换、查找下一个），以及 ⌘F（⌥⌘F 直接打开替换）。查找栏第一行是模式下拉（查找 / 替换 / 查找列）、查找输入框、上一个、下一个、“完成”。替换模式才有第二行：替换输入框、“替换”、“全部替换”；查找列模式没有第二行，也不能替换。模式下拉里还有大小写符合、高亮、递增搜索。递增搜索打开时，每输入一个字符就从当前单元格往后跳到下一个匹配；关掉时输入只更新高亮，要点上一个或下一个才移动。查找输入框回车等于“下一个”（查找列模式是下一个列）；替换输入框回车等于“替换”（替换当前这一处并跳到下一个）。“完成”或 Esc 关掉查找栏，并清掉高亮。替换只改当前页，写进网格后仍要提交。
- **表菜单**：只在表查看器激活时出现（10 第 9 节）。没开事务时是“开始事务”，开着时换成“提交”和“回滚”。然后是“设计表”（⌘D，M4 之前禁用）、“查询表”（⇧⌘Y：新开查询，写入 `SELECT * FROM 表`，标识符按方言加引号，目标是这张表的连接、库和模式，并运行）。筛选 ▸ 是“显示筛选与排序”（勾选，⌘⇧F）。排序 ▸ 对当前列升序、降序、不排序，和点表头同一条路径。然后是“应用筛选 & 排序”（⌃R）、“移除所有筛选 & 排序”、“刷新”（⌘R）、“停止”（⌘.）。⌘R 和 ⌘. 绑在表查看器的 key context 里，不落到导航树的刷新。

## 7. 复制与粘贴

- **复制**：⌘C 把选区复制为制表符分隔的文本。“复制为”子菜单提供 INSERT 语句、UPDATE 语句、TSV（仅数据、仅字段名、字段名和数据）。
- **粘贴**：多行多列的文本按当前选区的左上角对齐写入，超出已有行数时追加新行。
