# 架构基础优化：第一批

基线：`upstream/main` 的 `4c403de`；分支：`codex/architecture-foundations`。覆盖 F-CONN-011/012/020、F-PREF-010、F-DATA-003/004/009 与 F-QRY-006/007。保留现有 capability crate 分层与全量内存结果模型；M4 独立 PR 不纳入此分支。

## 1. 执行与会话安全

普通 `Relational::execute` 和用户 SQL 的 `execute_statement` 每次调用最多向当前物理会话提交一次。传输失败不重放原语句；写入响应丢失时返回可见错误，说明执行结果可能未知。事务、锁、临时表和会话设置不得因自动重连静默丢失。

应用明确知道无副作用、无会话依赖的元数据查询通过独立 `execute_read` 接口允许一次断线重连重试；不能按用户 SQL 的 SELECT 首词猜测安全性。驱动保守跟踪会话依赖：执行任意普通 SQL 后保持原物理会话，直到显式关闭；现有严格识别的 USE/search_path 初始化可恢复。ping 同样遵守此边界。保持独占编辑器会话，不引入全局连接池。

取消句柄应保持稳定，重连后指向新物理会话的取消凭据；关闭或不可用时不得继续向旧会话发送取消。取消不能等待正在执行 SQL 的主会话互斥锁。

应用生成的查询结果提交与对象 DDL 使用操作自己持有的短期会话，不复用共享元数据会话。每次操作只连接、执行一次并在结束时关闭；清理关闭失败只记录日志，不能把已经成功的写入变成可重试失败。表查看器和用户 SQL 保持原有独占会话。完成一次应用写入后，元数据会话仍可安全断线恢复，不重放写入。

操作任务登记到所属连接代际。关闭、重新打开或替换连接时同步撤销旧代际：尚在建立连接的操作不得继续进入业务闭包；已开始且尚未取得结果的操作停止执行剩余闭包，尽力取消服务器查询并关闭会话，返回会话丢失及结果可能未知的状态。已经取得业务结果后才发生撤销时，清理阶段仍保留该已知结果。新连接建立前等待旧代际操作的本机取消和清理结束；这不保证服务器已回滚。异步界面回调须核对连接代际，旧结果不得改写新会话的网格或忙碌状态。已经开始的连接初始化和 SQLite 阻塞任务须等待实际结算，不能用丢弃等待句柄代替清理；初始化 SQL 可能写入时保守标记结果未知。对象批量命令在语句之间也核对初始代际；任务开始前已关闭的连接仍按既有规则跳过，不新增整批失败提示。

本批保持当前 main 的公开接口源码兼容：旧 `navidog_connection::store_error_message` 保留为弃用转发入口；`DbError` 继续允许使用当前四个公开字段构造及穷尽解构，不在补丁中新增 `non_exhaustive` 限制。原公开 `run_once` 仅作为弃用兼容入口保留，仓库内部统一使用 `run_operation_rel`；以外部调用测试限定兼容用途。

`DbError` 保留驱动原始错误码与消息，并结构化标记会话丢失和执行结果未知；数据库层不拼接界面引导。查询、网格和导航器用自己的 en/zh-CN 文案呈现原始诊断及恢复说明。显式“重新打开连接”复用 Reopening 生命周期，保留编辑器选项卡、查询文本与本地未提交的行草稿；执行前说明原会话事务、锁、临时对象无法恢复，已执行语句的结果可能未知。重新提交保留的草稿前，用户须核对服务器实际状态；重新打开不能恢复旧事务或自动重放写入。

## 2. 配置保存事务

连接、连接组和主密码修改先构造候选配置，原子写入成功后才能替换当前内存配置与密钥并发布 Changed。失败向调用者返回错误，当前内存、密钥和磁盘原文件保持一致；不得把失败提示为成功。所有配置文件中的秘密均参与重新加密。

删除连接先保存移除结果，成功后再关闭会话、清理缓存和删除连接目录。修改配置文件的重连也只在保存成功后开始。多选操作使用单次候选保存，避免部分完成。保留现有文件格式，不扩展完整版本迁移。

按 ID 更新时，单个目标或批量中的任意目标不存在，均返回 NotFound 错误；在调用任何修改回调之前验证完整目标集合，拒绝时不写盘、不发布 Changed、不修改内存。空批量成功但不执行回调或保存。此处沿用既有无字段 `StoreError::NotFound`，不声称错误包含缺失 ID，也不在本批改动其公开变体。StoreError 的用户文案由 core 的 en/zh-CN 统一映射，日志 Display 与界面文案分离。

连接时保存密码失败不等于本次连接失败：仍使用本次输入的内存密码继续连接，关闭密码对话框并仅调用一次连接回调；通过本地化通知明确密码未保存。保存失败时持久配置保持不变。

## 3. 查询结果的数据与来源

GridModel 是当前结果行及隐藏列内容的唯一所有者；查询结果视图和表查看器不再保有可覆盖已提交结果的第二份行快照。排序与隐藏列重排同一套已接受数据。关闭“修改后同步记录”时，提交后的更新/插入/删除仍应在后续排序与隐藏/恢复列后保留；服务器生成的未知值仍按原规则重新加载。空白新增行不产生写入，隐藏或恢复列时保留该行及其默认值状态。

结果在运行时绑定 connection/database/schema 来源，固定旧结果不会随编辑器当前目标改变。刷新仅在来源与当前编辑器会话完全匹配时复用，以保留当前事务语义；否则按原结果来源建立独立会话、设置正确模式、查询后关闭。执行过程中改变选择不改变本次运行来源。脚本内成功执行已识别的 USE 或 SET search_path 后，从该物理会话读取实际数据库、当前模式及完整 search_path，后续结果绑定更新后的来源；工具栏选择保持不变。下一次运行未改变工具栏目标时沿用此会话上下文，显式改变目标时才按选择重设。独立刷新恢复完整 search_path，不把多模式路径简化为单个模式。来源探测失败不能把已成功的用户语句改为失败或重放；结果只允许在同一物理会话且上下文未再次变化时刷新，跨会话刷新拒绝执行并提示重新运行。

查询结果有未提交修改或空白新增草稿时，排序先结算正在编辑的单元格，再拒绝操作并显示“先提交或放弃修改”的本地化提示；保留当前行、草稿、选区及最近一次已接受排序的箭头状态。没有草稿的同步加载不属于拒绝条件，期间接受的新排序应在结果返回后继续应用。提交成功后的同步使用独立重载路径：先接受本次提交，再重新查询；重载失败不得重新提交已成功的写入。表查看器原有先提交再刷新的行为保持不变。

空白新增草稿不属于本次写入批次。接受成功写入以及同步替换数据时，仍保留这些草稿及未填写列的 DEFAULT 语义，覆盖关闭同步、同步成功和同步失败；重复同步不增加草稿数量，明确放弃修改时才移除草稿。只迁移空草稿数量与必要的选区信息，不复制已接受的结果行。

查询结果当前没有用户可调用的手动刷新入口，本批不声称交付该功能。内部刷新保护函数保留供后续接入，先结算活动输入、拒绝脏值，再避免并发启动第二次读取；回归仅证明其有待提交修改或空白草稿时拒绝且不发出 SELECT；公开刷新动作和菜单另行定义，不能直接重执行任意返回网格的写语句或 CALL。

隐藏列投影的成功或拒绝必须经 ResultGrid 返回给调用者。查看器仅在投影成功后发布新的隐藏列菜单状态；拒绝时保留原列、单元格值与待提交修改，空白未填写草稿仍允许投影。
